# Отчёт о сдаче: CRM-дашборд по сделкам для Битрикс24

## Ссылка на работающее приложение

**https://app-40572fab2785.vibecode.bitrix24.tech**

Приложение развёрнуто на платформе VibeCode, разворачивается внутри портала Битрикс24 и
работает от лица авторизованного пользователя (доступ даёт шлюз VibeCode; личность
подставляется в заголовок каждого запроса, собственный логин не требуется).

## Назначение и реализованные сценарии

Дашборд показывает аналитику по сделкам CRM текущего портала/пользователя:

- **Сводка по стадиям воронки** — количество сделок и их сумма по каждой стадии
  (`stageId`). Названия стадий берутся из живого справочника портала, поэтому кастомные
  коды (`C6:5`, `C123:2`, `ANOTHER_PRODUCT`) отображаются человекочитаемыми именами.
  Стадии раскрашиваются по семантике портала (успех — зелёным, провал — красным,
  остальные — нейтральным), а порядок повторяет канбан на портале.
- **Ключевые показатели** — общая сумма открытых сделок, количество выигранных сделок за
  выбранный период и средний чек по выигранным.
- **Последние сделки** — таблица из 15 последних сделок с названием, суммой, стадией и
  ответственным (ФИО); название ведёт на карточку сделки в портале. Таблица сортируется
  по любой колонке (клик по заголовку меняет направление) и вытянута на всю ширину —
  все колонки видны полностью. Расположена справа от воронки.
- **Фильтр по периоду** — по дате создания сделки (всё время / 30 / 90 / 180 дней /
  текущий год); корректно пересчитывает все блоки.
- **Фильтр по воронке** — по умолчанию выбрана воронка «Продажи услуг (общее)» (общая
  воронка портала, `categoryId 0`), список направлений доступен в выпадающем списке.
- **Фильтр по стадии воронки** — выпадающий список стадий текущего среза; выбор
  конкретной стадии сужает KPI, воронку и таблицу до сделок этой стадии.
- **Переключатель «Все / Мои сделки»** — срез по сделкам текущего авторизованного
  пользователя.
- **Тёмная / светлая тема** — переключается кнопкой в шапке, по умолчанию следует
  системной настройке, выбор запоминается в браузере.

На живом портале в момент проверки: сумма открытых сделок **409 504 ₽** (6 в работе),
выиграно за период **161** на **8 040 377 ₽**, средний чек **49 940 ₽**, всего по воронке
**248 сделок** за снимаемый период.

## Запрошенные скоупы и их обоснование

- **`crm` (чтение сделок и стадий)** — единственный необходимый скоуп: приложение только
  читает сделки и справочник стадий через REST-прокси (`/deals/search`, `/statuses`),
  ничего не пишет и не изменяет в портале.
- **`user` и собственный логин/пароль не требуются** — личность авторизованного
  пользователя приходит из заголовка шлюза `X-Vibe-User-Id`.

Обоснование: минимальный набор прав снижает поверхность атаки и соответствует принципу
наименьших привилегий. Ключ доступа (`BITRIX_API_KEY`) живёт только в окружении сервера и
в браузер не попадает.

## Известные ограничения

- Снимок строится по сделкам выбранной воронки, созданным за последние ~3 года
  (ограничивает время первичной сборки на больших порталах); более старые сделки в
  статистику не попадают.
- Данные обновляются фоновым снимком раз в ~5 минут, а не в момент открытия страницы.
- Ответственный показывается полным именем (ФИО) из справочника сотрудников портала;
  если имя не найдено — выводится ID.
- Если стадии нет в справочнике портала, используется резервный словарь; в крайнем
  случае показывается сам код.

## Инструкция для проверяющего

1. Откройте `https://app-40572fab2785.vibecode.bitrix24.tech` (вход даёт шлюз VibeCode).
2. Убедитесь, что видны три KPI-карточки, воронка по стадиям с количеством и суммами и
   таблица последних сделок (10–20 строк) справа от неё со всеми колонками.
3. Кликните по заголовкам колонок таблицы — строки пересортятся.
4. Выберите период / воронку / стадию в фильтрах — все блоки пересчитаются.
5. Переключите «Все / Мои сделки» — срез сузится до сделок текущего пользователя.
6. Кликните по кнопке «Тема» — интерфейс переключится между тёмным и светлым.
7. Кликните на название сделки — откроется её карточка в портале Битрикс24.

Исходный код — в репозитории проекта (файлы `server.js`, `public/*`, `package.json`,
`README.md`), без ключей и секретов (`.env` в `.gitignore`, ключ читается из окружения).
